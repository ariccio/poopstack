# p(oop)stack: a bathroom-humor mod for Claude Code (plan)

This is the public copy of the approved plan (approved 2026-10-21). It leaves out private material: other repositories, local paths, session identifiers, usage figures and internal review records. Where the private plan quotes the author's rulings, this copy states the outcome.

## Context

- **The concept (2026-10-19):** Claude Code's whimsical progress words ("Sauteing…", "Cooked for 1m 6s") become bathroom puns that double as programming jokes, chosen from what Claude is actually doing, done properly. It lives in a public GitHub repository with a small set of strict engineering gates, is cross-checked by outside reviewers, and is built to be shared.
- **Research behind this plan:**
  - **The theme is nearly free:** no catalogued mod takes the bathroom as its theme (0 of 5,898 by a name-and-description search on 2026-10-20; the count moves daily). Neighbours exist: peemodoro (a pee-break timer on the status line), slapbox (a cartoon butt) and slowpoke-tamagotchi (a poop chore). Every mechanic exists somewhere, so the edge is lines chosen from real events.
  - **What spreads:** every pure-joke mod checked sat at 0 to 4 GitHub stars; the playful projects that spread were also useful (a sound-notification tool at 5,086 stars, a status line at 13,351). A joke keyed on model behaviour dies when the model changes. Since Claude Code 2.1.144 the `spinnerVerbs` setting no longer touches the closing line, so only a mod's `TurnDuration` hook can change it.
  - **Engine facts:** from the Claude Code 2.1.304 plugin type declarations; anything unproven is probed in M0. Claude Code 2.1.305 was current on 2026-10-20, so M0 re-checks every cited line against the running build.
  - **Humor science:**
    - both readings of a pun backed by distinct words (Kao, Levy and Goodman 2016);
    - the real event is the setup (He, Peng and Liang 2019);
    - euphemism over explicitness (McGraw and Warren 2010);
    - variety and grouping by event slow wear-out (Redden 2008).

## Name and stylization

- **"p(oop)stack"** appears in `displayName` in both `plugin.json` and the marketplace entry (shown in the UI in place of `name`, any casing), and in the README title, the repository description, the footer label, the toasts, the report card and the social card.
- **Plugin and command names stay `poopstack`:** they allow only letters, digits, `_` and `-`.
- **Extra command names** are separately registered names served by the same hook (`CommandSpec` has no alias field). Each is registered alone and skipped if another plugin holds it; the crude ones only in maximum. M0 probes what happens on a collision.
- **README credit:** an affectionate parody of Lauren Tan's (poteto) pstack, not affiliated. No command starts with `poteto`.

## Design contract: goofy but correct

1. **Jokes decorate; they never hide real information.**
   - The status `message`, desktop step text, waiting-for-agents line, clock, errors and refusals stay visible and true.
   - The mod must not lie to the user.
2. **Never break Claude Code.**
   - No hook gates a tool call or a prompt.
   - Every `ui.render` hook passes through on anything unexpected and has a `.catch` that passes through.
   - The `tool.call` observer writes its state before `await next(e)`, returns the result unchanged, and its `.catch` uses `next.called`.
   - Never touched: tool rows, message rows, AskUserQuestion, permission dialogs, PromptHint's `hint`.
3. **The model never sees a joke** in the core mod.
   - No `prompt.compose`, no prompt context, no `attribution.text`.
   - `/poopstack` returns neutral, true `text` and draws the joke as a `CommandOutput` tree.
   - Only an explicitly installed persona pack (phase 4) may change this, and it says so.
4. **Off, at once.**
   - `enabled` is declared in `userConfig`, and `/poopstack` is registered `immediate: true`.
   - `off` writes the config through `$.config.set`, checks the result, and stops timers and sound.
   - The README also gives the plugin-disable route.
   - "At once" is measured live.
5. **The phrase priority rule** (no flicker):
   - One base phrase per turn.
   - A tool-context overlay applies only while that tool runs and clears on completion.
   - Long-wait stages apply only to the live turn, as a growing suffix; the word itself never changes mid-turn.
   - The footer pairs with what this rule showed.
6. **Pairing honesty.** `TurnDuration` carries no turn id. Matched footers ship only if the M0 probe proves a reliable join; otherwise a row gets an independent past-tense joke, never presented as "matched".
7. **Vocabulary review**, per entry:
   - a grammar test (a durative past form that reads right before "for 42s");
   - a meaning review: what real event makes both readings true, and could it be mistaken for a real failure?
   - ASCII text plus two named UI marks, the ellipsis "…" and the middle dot "·", each with an ASCII fallback where a surface needs one; the 🚽 only in the footer label outside discreet;
   - a column cap;
   - a block-list of words and shapes: no line shaped like a shell command, no line naming a real destructive operation, no copy of a real Claude Code status string (Retrying, Overloaded, Compacting, "blocked by hook"), and cut words ("sphincter", "excretion", "core dump", "backup", "force"; "brown" never in discreet).
   - One meaning per word: "ply" is the rate-limit paper meter only; "pressure" is effort; "stalls" are subagents; "floor" is sessions; "days running" is the streak.
8. **Repetition:**
   - a per-session shuffle bag in `$.state`;
   - a short "recently shown" list in `$.store`, which is per-plugin, machine-wide and has no compare-and-set, so it is merged on read and race-tolerant;
   - lines grouped by event;
   - legendary rarity.
9. **Counter honesty.**
   - "Movements" counts main-agent turns.
   - Session counts are exact; lifetime totals are labelled approximate.
   - Only ids and aggregates are stored, never prompts, paths, commands or output.
   - The report card is copied only through a button (`$.ui.copy`).
10. **Surfaces:**
    - Spinner on terminal, desktop and VS Code, replacing only "Working" off the terminal.
    - TurnDuration on the terminal only.
    - SessionMode and AbovePrompt on terminal and desktop.
    - Raster and Image on the terminal only, with a `Text` fallback elsewhere.
    - Mobile is untouched.
    - A matrix goes in the README.
11. **Presets** (a matrix across words, footer, toasts, animation and sound):
    - `discreet` drops the 🚽 and the unmistakable jokes; on a joked turn its footer shows the plain text `p(oop)stack`; on a plain turn Claude Code's own line shows untouched, and whether the mod is on shows in `/poopstack` status ("on · discreet · jokes on about 1 turn in 10");
    - `regular` is the default;
    - `maximum` is opt-in.
    - Accessibility keys (`axScreenReader`, `prefersReducedMotion`) and `spinnerVerbs` are probed before they are relied on.

## Architecture

```
poopstack/                                  repository root = marketplace + dev tooling
  .claude-plugin/marketplace.json           name poopstack; entry { name: poopstack, displayName: "p(oop)stack", source: "./plugins/poopstack" }
  plugins/poopstack/                        the mod (no node_modules inside the watched folder)
    .claude-plugin/plugin.json              name, displayName, version, description, userConfig (enabled, preset, sound), "types"
    hooks/hooks.json                        { "modules": ["./register.tsx"] }
    hooks/register.tsx                      wiring only
    hooks/vocabulary.ts  pick.ts  format.ts  flush.ts   data + pure logic
    types/index.d.ts                        PluginState contract
    tests/*.test.ts(x)                      claude plugin test
    tsconfig.json                           extends the engine-laid .claude-plugin/types/tsconfig.json + strict overlay
  scripts/ (require-tool.zsh, validate-commit-message.zsh + test, git-improvements.zsh + test, security-gitleaks.zsh)
  ast-grep-rules/  sgconfig.yml  biome.json  .editorconfig  lefthook.yml  .gitleaks.toml  package.json (pnpm, dev only)
  CLAUDE.md  AGENTS.md  .claude/settings.json  .claude/rules/error-handling.md
  README.md  LICENSE (MIT)  CONTRIBUTING.md  CHANGELOG.md  docs/design.md  docs/planning/  docs/demo/
```

**Error lanes:**
- Our broken invariant throws inside the hook. The engine draws its own and names the plugin, which is loud.
- Anything shared with the world (`$.audio.play` rejecting, `$.settings.read`, `$.store`) is validated and handled visibly.
- No success-shaped defaults.

## Repository setup: a minimal set of strict gates

1. **tsconfig:** the strict battery as an overlay on the engine's config. Back off one flag at a time, on evidence only.
2. **Formatting and lint:** Biome and `.editorconfig`.
3. **ast-grep:** `no-ts-ignore`, `no-reasonless-suppression`, `no-as-any`, `no-as-unknown-as`, `no-empty-catch`, `no-catch-swallow`, `no-catch-return-default` (error). Each one is watched failing once before it is trusted.
4. **lefthook** (every binary through `require-tool.zsh`, so a missing tool fails loudly):
   - pre-commit: Biome, ast-grep, `tsc`, gitleaks on staged files;
   - commit-msg: a conventional-commit validator;
   - pre-push: `claude plugin validate --strict`, `claude plugin test`, full gitleaks, `lefthook validate`, script tests;
   - post-checkout and post-merge: `git-improvements.zsh`.
5. **`.claude/settings.json`:** a destructive-git deny set; `--force-with-lease` (both forms) at ask; `plansDirectory: docs/planning`.
6. **Docs:** a short CLAUDE.md, `.claude/rules/error-handling.md`, AGENTS.md as a pointer.
7. **Skipped, with reasons:** a worktree-safe installer, coverage floors, ESLint's type-aware lane, cspell, semgrep, oxlint.
8. **Tool versions:** pinned, each release at least 14 days old.
9. **Type-check venue:** `tsc` runs only where the engine has laid its types; CI says so.

## Milestones

### Phase 1, core → `v0.1.0` (unannounced public push)

**M0. Measure and bootstrap.**
1. Bootstrap: this repository with an initial commit on `main`, a `phase-1` worktree, and this public plan copy.
2. **The probe mod** (observe only, logging to a local scratch file). It measures:
   - the `Spinner.message` values and the request ids;
   - a `TurnDuration`↔`turn.complete` join;
   - whether the engine's two words are one draw;
   - re-render counts;
   - WAV playback (a shipped file or base64 bytes);
   - command-name collisions, what `$.command.list()` shows, and which wins when two plugins, a user command file or an MCP prompt share a name;
   - whether hidden names still run when typed in full, and whether a capitalised name answers to its lowercase spelling;
   - the accessibility settings keys;
   - whether `$.store` is one store per machine or one per load route;
   - where `$.ui.status` draws and whether an empty status clears;
   - whether the engine already uses `Spinner.suffix` for something true (its retry suffix is the known case);
   - whether a toast raised in `session.end` for `/clear` is drawn, and which surfaces draw toasts;
   - whether an organization's policy settings are readable from a user mod;
   - whether the closing line keeps "{word} for {duration} · done {time}" when the word is rewritten, and how a two-sentence closing line draws before "for 42s";
   - whether the VS Code label for rewritten UI uses `name` or `displayName`;
   - whether `turn.complete`'s `{ text }` reaches the model (the core mod avoids it until proven);
   - whether `$.state` survives a compaction inside one session (it gates the commit pair's counter).

   Interrupted and subagent turns are measured with a person at the keyboard.
3. **Re-forecast:** the work done so far is measured and the remaining estimates are redone from it.

**M1. Gates.** Repository setup items 1 to 6. `pnpm install` and `lefthook install`. Each gate and rule is watched failing once, separately. Measure the runtime of `claude plugin test`.

**M2. Core rows 1, 2 (if proved), 3, 4, 4a, 4b, 6a, 7, 8**, with tests:
- the surfaces loop;
- the pass-through cases (non-null `message`, desktop step text, `isExpanded`, `waitingFor`, switch off, a throwing internal);
- the pairing join or the honest fallback;
- a shuffle bag with no repeats; the engagement dice, seeded;
- off mid-turn;
- deny, error, interrupt and overlap for the observer;
- the pass-through chain: for every observer at `tool.call`, `prompt.submit` and `session.receive`, exactly one `next(e)` with unchanged input and an unchanged result, across success, deny, throw, interruption, backgrounding and `off`; no awaited decorative work before `next`.

About 50 curated phrases, through the meaning review.

**Phase-1 landing:**
- An outside code review (Codex), one targeted repair, and the author's live look.
- The sharing steps: a secret scan, every staged file read, and gitleaks.
- **Before `v0.1.0`, because phase 1 is already a public push:** the off-and-uninstall matrix (mid-turn `off` stops spinner and footer rewrites, timers, sound, status, toasts, panes and future store writes; a refused `$.config.set` reports failure instead of claiming off; reload, `/clear`, update, disable, uninstall and reinstall from a clean profile), and the README's privacy statement checked against what the code stores.

## Verification (each claim names its venue)

2. `claude plugin test`: green, with the surfaces loop.
3. `tsc -p plugins/poopstack` against the engine-laid types: green locally (CI cannot run it).
4. The lefthook gates: green on a real commit and a real push, each watched failing once first.
5. **The live matrix:**
   - terminal, desktop, and VS Code if available; a narrow terminal; a screen reader and reduced motion; a mobile session that stays untouched (the test kit exercises hooks and trees, not what a surface paints);
   - headless (silent);
   - abort, resume, hot reload;
   - off mid-turn;
   - the suffix stages;
   - the pairing or its honest fallback.

   The probe's log is the evidence for the engine facts; a person's eyes are the evidence for the look.
6. The flush: listened to; macOS only.
